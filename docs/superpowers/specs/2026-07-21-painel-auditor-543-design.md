# Painel do Auditor — Qualificação (spec 5.4.2.5)

Data: 2026-07-21
Escopo: OPS-CTR-FOR-002 §5.4.2.5 — Painel de Acompanhamento do Ciclo (Visão do Auditor).

## Contexto

O módulo Qualificação (`src/pages/qualificacao/`) hoje roteia `admin` e `auditoria` para o mesmo `GestorDashboard` (Dashboard Estratégico da Rede). Existe um `AuditorView.tsx` acessível apenas via toggle interno (`Acessar Painel do Auditor`) que é uma listagem simples de instâncias, sem KPIs.

O motor `eval_*` (novo, RN630) não tem entidade "ciclo". A tabela `qualification_cycles` existe mas pertence ao sistema paralelo antigo e não deve ser confundida.

Esta spec cobre: painel do auditor com KPIs agregados, listagem, exportação `.xlsx`, e uma sub-tela de gestão de ciclos. Reorganiza a navegação do módulo em abas, elimina `AuditorView` legado e introduz a entidade `eval_cycles`.

## Estrutura e navegação

`src/pages/qualificacao/index.tsx` deixa de decidir por role. Passa a ser container fino:

- Prestador/cooperado → `PrestadorView` (inalterado).
- Staff (admin + auditoria) → novo container `QualificacaoStaff` com header e três abas:

| Aba | Componente | Home de |
|---|---|---|
| Estratégico | `GestorDashboard` (atual, sem alteração de conteúdo) | admin |
| Painel do Ciclo | `PainelDoCiclo` (novo, spec 5.4.2.5) | auditoria |
| Ciclos | `CiclosAdmin` (novo, CRUD de `eval_cycles`) | — |

Aba selecionada persiste na querystring (`?aba=painel-ciclo`) — deep link e refresh preservam contexto sem introduzir `react-router`. Ambos os perfis staff enxergam as três abas; não há restrição de permissão por aba nesta versão.

## Schema — Migration `0019_eval_cycles.sql`

```sql
CREATE TABLE eval_cycles (
  id          bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  label       text NOT NULL,
  start_date  date NOT NULL,
  end_date    date NOT NULL,
  active      boolean NOT NULL DEFAULT false,
  created_at  timestamptz NOT NULL DEFAULT now(),
  CHECK (end_date >= start_date)
);
CREATE UNIQUE INDEX eval_cycles_one_active ON eval_cycles (active) WHERE active;

ALTER TABLE eval_instances
  ADD COLUMN cycle_id bigint REFERENCES eval_cycles(id) ON DELETE SET NULL;
CREATE INDEX eval_instances_cycle_idx ON eval_instances (cycle_id);
```

**Backfill (na migration, idempotente):** insere `('Ciclo 2026', '2026-01-01', '2026-12-31', true)` se `eval_cycles` estiver vazia; `UPDATE eval_instances SET cycle_id = <novo> WHERE cycle_id IS NULL`. Instâncias antigas caem no ciclo atual — comportamento esperado.

## Endpoints

Todos protegidos por autenticação. Perfis `admin` e `auditoria` acessam os endpoints de ciclo e de dashboard. Reopen exige `auditoria` ou `admin`.

| Método | Rota | Descrição |
|---|---|---|
| GET | `/api/eval/cycles` | Lista ciclos com `{id, label, start_date, end_date, active, instances_count}`. |
| POST | `/api/eval/cycles` | Cria ciclo. Se `active=true`, desativa o ciclo ativo anterior na mesma transação. |
| PATCH | `/api/eval/cycles/:id` | Edita `label`, `start_date`, `end_date`, `active`. Ao ativar, desativa o anterior. |
| DELETE | `/api/eval/cycles/:id` | Falha com 409 se houver `eval_instances` com esse `cycle_id`. |
| GET | `/api/eval/dashboard/auditor?cycle_id=<id>` | Payload do Painel do Ciclo. Sem `cycle_id` → ciclo ativo. |
| POST | `/api/eval/instances/:id/reopen` | Ação "Editar/Devolver". Muda status para `aguardando_evidencia`. Registra em `access_logs` (action, meta, auditor_id). |
| GET | `/api/eval/dashboard/auditor.xlsx?cycle_id=<id>` | Buffer `.xlsx` com as 11 colunas da spec. |

### Mapeamento dos KPIs → dados

- **`total_locations`**: `COUNT(DISTINCT (provider_id, location_id))` das instâncias no ciclo. `location_id NULL` conta como "prestador inteiro" (1 linha). Uma linha por unidade quando `location_id` presente.
- **`sent` / `pending`**: `sent` = instâncias com status ∈ `{em_analise, aguardando_evidencia, aprovado, reprovado, finalizado}`; `pending` = `em_andamento` + `pendente`. O front deriva o percentual (`sent / (sent + pending)`).
- **`in_review`**: `status='em_analise'`.
- **`awaiting_provider`**: `status='aguardando_evidencia'`. Interpretação da spec ("aguardando reanálise do prestador").
- **`avg_score`**: `AVG(percentual)` das instâncias com `status <> 'em_andamento'`.
- **`low_security_count`**: instâncias com % da dimensão `Segurança` < 60. Fórmula abaixo.
- **`seal_distribution`**: `GROUP BY seal`, incluindo instâncias com `seal IS NULL` como "Não Qualificado" apenas quando `status IN ('reprovado')`; demais nulls ficam fora.
- **`group_distribution`**: `GROUP BY p.provider_group` das instâncias no ciclo, distinct por `(provider_id, location_id)`.

### Cálculo de `%` por dimensão

Usado em `low_security_count` (KPI) e nas colunas `% Segurança / % Conforto / % Experiência do Cliente` do export.

```sql
SELECT ea.instance_id, eq.dimension,
       SUM(ea.score_obtained) / NULLIF(SUM(eq.max_score), 0) * 100 AS pct
  FROM eval_answers ea
  JOIN eval_questions eq ON eq.id = ea.question_id
 WHERE ea.answer_value <> 'NA'
 GROUP BY ea.instance_id, eq.dimension;
```

`answer_value = 'NA'` fica fora do denominador — mesma regra do `computeScore` (`src/lib/score.ts`).

## Export `.xlsx`

Backend gera com a lib `xlsx` (já em `package.json`, usada pelo import de roteiros). Colunas fixas na ordem da spec:

```
Município | Logradouro | Prestador | Código | Pontuação Total |
Classificação | % Segurança | % Conforto | % Experiência do Cliente |
Data de Envio | Data de Conclusão da Análise
```

- **Pontuação Total** = `percentual` da instância (0–100).
- **Classificação** = `seal` (Ouro/Prata/Bronze) ou vazio.
- **% Segurança / Conforto / Experiência do Cliente** = da tabela dimension-per-instance. Vazio quando denominador da dimensão for zero (roteiro sem critérios daquela dimensão).
- **Data de Envio** = `eval_instances.started_at` da primeira transição para `em_analise` (pragmático: `completed_at` quando existir, senão vazio). `ponytail:` refinar com trilha de transições se auditoria pedir.
- **Data de Conclusão da Análise** = `completed_at` quando `status IN ('aprovado','reprovado','finalizado')`.
- **Logradouro** = `provider_locations.address` quando `location_id` presente; senão endereço do prestador (`providers.address`).
- Nome do arquivo: `painel-ciclo-<slug-do-label>-YYYYMMDD.xlsx`.
- Sem merges/cores/formatação — a spec não pede.
