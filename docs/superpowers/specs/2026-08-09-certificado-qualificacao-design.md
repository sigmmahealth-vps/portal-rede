# Certificado de Qualificação (spec 5.4.5) — Design

**Data:** 2026-08-09
**Escopo:** Sprint 4 (Onda 1 · RN 630) — penúltima pendência da S4 (resta Pesquisa de Satisfação).

## Objetivo

Ao encerrar com aprovação o ciclo de qualificação (parecer final), o sistema emite
automaticamente um certificado digital por unidade avaliada. O prestador vê os
certificados na aba **Certificados** do módulo Qualificação da Rede, baixa o PDF
(versão para impressão) e qualquer pessoa pode verificar a autenticidade por um
QR code que aponta para uma página pública de verificação.

## Decisões de produto (validadas com o usuário)

1. **Quem ganha certificado:** toda avaliação finalizada pelo parecer, inclusive selo
   Bronze. Bronze é um selo válido na régua 5.4.2.3.
2. **Autenticidade:** código de verificação único e aleatório por certificado; QR code
   aponta para página pública `/verificar/:codigo` (sem login). Assinatura digital
   ICP-Brasil está fora de escopo.
3. **PDF:** página de impressão HTML/CSS (A4 paisagem) + `window.print()`. Sem lib de
   PDF. A arte é uma versão simples com a paleta Unimed; a arte final virá da equipe
   da Operadora depois (troca de CSS/fundo, sem mudança de dados).
4. **Validade:** `end_date` do ciclo do certificado **+ 1 ano** (ex.: Ciclo 2026
   termina 31/12/2026 → validade 31/12/2027). Não depende do ciclo seguinte existir.
   Fallback para instância sem ciclo: `completed_at + 1 ano`.
5. **Emissão retroativa:** instâncias já aprovadas antes desta feature ganham
   certificado via backfill na migration, com `issued_at = completed_at`.

## Arquitetura

Abordagem escolhida: **tabela mínima `eval_certificates` + emissão no parecer +
backfill** (mesmo padrão do Plano de Ação 5W2H: tabela própria, geração na transação
do parecer, evento de auditoria).

### Migration `0025_eval_certificates.sql`

```sql
CREATE TABLE IF NOT EXISTS eval_certificates (
  id           bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  instance_id  bigint NOT NULL UNIQUE REFERENCES eval_instances(id) ON DELETE CASCADE,
  verify_code  text   NOT NULL UNIQUE,   -- 32 chars hex aleatórios
  issued_at    timestamptz NOT NULL DEFAULT now(),
  valid_until  date   NOT NULL,
  created_at   timestamptz NOT NULL DEFAULT now()
);
```

- **Sem snapshot** de selo/percentual/nomes: tudo vem por JOIN de `eval_instances`
  (imutável após o parecer), `providers`, `provider_locations`, `eval_cycles`.
- **Backfill na própria migration:** para cada `eval_instances` com status
  `aprovado`/`finalizado` sem certificado, insere com
  `verify_code = replace(gen_random_uuid()::text, '-', '')`,
  `issued_at = completed_at` (data honesta) e `valid_until` pela regra da decisão 4.

### Emissão no parecer

Em `POST /api/eval/instances/:id/parecer`, dentro da transação existente (a mesma do
UPDATE de status + plano de ação):

```sql
INSERT INTO eval_certificates (instance_id, verify_code, valid_until)
VALUES ($1, $2, $3)
ON CONFLICT (instance_id) DO NOTHING
```

- `verify_code` gerado com `crypto.randomBytes(16).toString('hex')` (stdlib).
- `valid_until` calculado em `src/lib/certValidity.ts` (função pura, testável).
- Após o commit, `auditLog` com action `certificate_issued`
  (meta: provider_id, instance_id, certificate_id, seal, valid_until) — fora da
  transação, como os demais logs do parecer.
- Parecer re-executado → `ON CONFLICT DO NOTHING`, não duplica.

## API

### `GET /api/eval/certificados?cycle_id=N` (autenticado, prestador)

Lista os certificados do prestador logado no ciclo (um por unidade avaliada):

```json
[{
  "id": 1, "verify_code": "ab12…",
  "seal": "Prata", "percentual": 85,
  "cycle_label": "Ciclo 2026",
  "provider_name": "Dr. João Silva",
  "location_label": "Matriz - SP",
  "location_address": "Rua Antônio de Lucca, 50, Pio Correa - Criciúma",
  "issued_at": "2026-05-25", "valid_until": "2027-12-31",
  "dimensions": [{ "dimension": "Segurança", "pct": 80.0 }]
}]
```

- Desempenho por dimensão: reaproveita a query por dimensão existente +
  `mergeSecurityDL` (Documento Legal consolidado em Segurança).
- `location_address` montado de `provider_locations`
  (logradouro, numero, bairro, cidade).
- Sem `cycle_id` → ciclo ativo. Staff não tem visão própria nesta fase.

### `GET /api/certificados/verificar/:code` (público, sem login)

- Código existe → `{ valido: true, expirado: bool, seal, percentual, provider_name,
  location_label, cycle_label, issued_at, valid_until }`.
- Código não existe → `{ valido: false }` (sem vazar mais nada).
- Certificado expirado continua verificável: `valido: true, expirado: true` — a
  página mostra "expirado em DD/MM/AAAA", não "inválido".
- Rate-limit reaproveitando o helper `rateLimit` do auth (endpoint aberto).

## Frontend

### Aba "Certificados" no `PrestadorView.tsx`

Substitui o placeholder "Em breve":

- Seletor de ciclo no topo (padrão das outras abas).
- Um card por unidade, seguindo o mockup da Tela 1: cabeçalho com selo
  ("QUALIFICAÇÃO REDE CREDENCIADA · Prata"), "Certificamos que **{prestador}**,
  unidade: {unidade}", ciclo, pontuação final, data de emissão, validade,
  "Desempenho por Dimensão" (3 linhas com percentuais), QR code (data-URL apontando
  para `{origin}/verificar/{code}`) com legenda "Autenticidade Verificada · Assinado
  Digitalmente", e botão **PDF**.
- Estado vazio: "Nenhum certificado neste ciclo ainda".

### Certificado para impressão — rota `/qualificacao/certificado/:id/imprimir`

O "PDF" do botão. Página A4 **paisagem** em HTML/CSS (arte simples, paleta Unimed),
estrutura da arte de referência da Operadora:

- Título "CERTIFICADO — Avaliação, Qualificação e Desenvolvimento dos Prestadores".
- Badge do selo (Ouro/Prata/Bronze).
- Nome do prestador + endereço da unidade.
- Percentual de cada dimensão com os textos descritivos fixos da arte de referência
  (Segurança / Conforto / Experiência do Cliente).
- Percentual total, legenda de classificação (faixas: Ouro > 90,00% · Prata 60,01% a
  90,00% · Bronze até 60,00%), validade.
- Duas assinaturas em texto (linha + nome + cargo): Diretor Presidente e
  Vice-Presidente — sem imagem de assinatura por ora.
- QR code de verificação discreto no rodapé.
- Ao abrir, chama `window.print()`; o usuário salva como PDF.
- Quando a arte final chegar, troca-se apenas o CSS/fundo desta página.

### Página pública `/verificar/:codigo`

Rota sem login (mesmo esquema da Política de Privacidade). Consulta a API e mostra:
válido (selo, prestador, unidade, ciclo, emissão, validade), expirado (aviso com a
data) ou inválido (código não encontrado).

### Dependência nova

- `qrcode` (npm) — gera o QR como data-URL no cliente. Única dependência nova.

## Testes

Padrão do projeto (`node --test`, registrados no script `test` do package.json):

- `src/lib/certValidity.test.ts` — validade = fim do ciclo + 1 ano; fallback
  `completed_at + 1 ano` sem ciclo.
- Formato do código de verificação (32 hex) e não-duplicação na emissão.
- `computeSeal` e `dimensionAgg` já têm testes próprios — não duplicar.

## Tratamento de erros

- Verificação com código inexistente → `{ valido: false }` seco.
- Rate-limit no endpoint público.
- Parecer re-executado → certificado não duplica (`ON CONFLICT DO NOTHING`).
- Instância sem `location_id` → card e certificado mostram só o prestador, sem
  linha de unidade/endereço.
